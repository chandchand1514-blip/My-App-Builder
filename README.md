# My App Builder

A web-to-Android wrapper builder using Capacitor and GitHub Actions. It creates a debug-signed APK for testing from an HTTPS website URL.

## Builder features

- App name, Android package ID, version, orientation
- App icon, theme color, splash background and duration
- Android permissions and optional Capacitor plugins
- Custom-scheme login callback (example: `staffpro://auth/callback`)
- Optional HTTPS Android App Link
- Full-screen mode
- APK output, or APK plus a debug AAB for testing

The callback URL adds an Android VIEW/BROWSABLE intent filter. If a callback or App Link is set, the build also includes the Capacitor App plugin. The website itself must still listen for the app-open callback and complete its authentication flow; wrapping a website does not automatically rewrite its OAuth code.

## Render environment variables

Set these in the Render Web Service environment:

- `GITHUB_REPO`: `owner/repository` for this repository
- `GITHUB_TOKEN`: GitHub token with Contents: Read and write access to this repository (needed for repository_dispatch and release publishing)
- `SESSION_SECRET`: a long random secret for the optional Builder Google-login session
- `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`: optional; only needed for the Builder's own Google login route
- `GOOGLE_CALLBACK_URL`: optional override; otherwise the Render callback URL in server.js is used
- `ADMIN_API_KEY`: optional secret header required by the release-delete API

Do not put these secrets in frontend HTML or commit them to Git.

## Google / Supabase callback setup

For a Supabase-backed website using Google OAuth:

1. In Supabase Authentication → URL Configuration → Redirect URLs, allow the app callback, e.g. `staffpro://auth/callback`.
2. In the website's Supabase OAuth call, use the same app callback as `redirectTo` when running inside the APK.
3. In Google Cloud Console, the Authorized redirect URI remains the Supabase Auth callback, usually `https://PROJECT-REF.supabase.co/auth/v1/callback`. Do not replace this with the custom app scheme.
4. The website must handle the deep-link return and finish the Supabase session flow. The Builder adds Android intent-filter registration but cannot modify the hosted website's JavaScript.
5. For HTTPS App Links, host `/.well-known/assetlinks.json` with the correct package ID and signing-certificate SHA-256 fingerprint. The fingerprint depends on the APK signing key.

## Build and deployment

1. Merge the Builder update into `main`.
2. Deploy the Node.js service on Render with `npm install` and `npm start`.
3. Ensure Render points at this GitHub repository and has the environment variables above.
4. Open the Builder website, fill the numbered sections, and select **APK BANAYEIN**.
5. The server sends a `repository_dispatch` event. GitHub Actions builds the APK and publishes it as a GitHub Release.
6. Download the APK from the Builder's Apps list.

The pull-request workflow also builds a sample APK for validation and uploads it as a workflow artifact.

## Important signing note

The APK generated by the current workflow is **debug-signed** and intended for testing. The optional AAB is also a debug build and is not ready for Play Store publishing. Production distribution requires a protected release keystore and a separate signing configuration. Never commit keystores or signing passwords to the repository.
